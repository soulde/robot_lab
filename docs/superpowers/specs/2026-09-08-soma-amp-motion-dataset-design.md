# SOMA AMP Motion Dataset Design

## Goal

Add an explicit SOMA-format expert-motion loader to the local RSL-RL AMP
implementation while preserving the existing BeyondMimic loader and its
loading behavior.

The SOMA loader consumes the standard NPZ output generated by
`soma-retargeter`. Dataset generation, including any frame-rate conversion,
remains outside RSL-RL.

## Scope

This change adds the loader, its public export, and the AMP configuration
factory needed to select it. It does not:

- resample, interpolate, decimate, or otherwise control motion frame rate;
- change the existing BeyondMimic `MotionDataset` behavior;
- automatically switch an existing robot task to the SOMA dataset;
- modify generated SOMA files;
- start training or alter existing checkpoints and logs.

## Data Contracts

### Shared AMP tensor fields

Each SOMA NPZ supplies the same numerical arrays consumed by the current AMP
pipeline:

- `fps`
- `joint_pos`
- `joint_vel`
- `body_pos_w`
- `body_quat_w`
- `body_lin_vel_w`
- `body_ang_vel_w`

The loader treats adjacent source frames as one AMP transition. It records the
source FPS for metadata but does not compare or convert it against the
simulation control frequency. Compatible sampling is the responsibility of
the data-generation command in `soma-retargeter`.

### SOMA name metadata

SOMA NPZ files must additionally contain:

- `joint_names`
- `body_names`

The task configuration continues to pass both the expected joint contract and
the complete body contract. For the new DR02 SOMA files this means 29 joints
and the new 34-body list, including `neck_link`, `head_link`, `left_toe_link`,
and `right_toe_link`.

The configured body order must exactly equal the embedded SOMA body order.
This explicit validation prevents a 30-body BeyondMimic contract from being
silently applied to a 34-body SOMA tensor. The loader does not reorder body
arrays and does not change the old loader's body logic.

The configured joint names must contain the same names as the embedded joint
metadata. Joint positions and velocities are reordered into configured joint
order using the existing AMP joint-contract behavior.

## Architecture

### `SomaMotionDataset`

Add `rsl_rl/datasets/soma_motion_dataset.py` in the local RSL-RL fork. The
class presents the same constructor and `sample_amp_observations(batch_size)`
interface as the existing `MotionDataset`.

The SOMA-specific layer performs strict metadata validation before delegating
the numerical loading and AMP feature construction to the existing loader:

1. Resolve the selected NPZ basenames using the same regex/list semantics.
2. Require all shared numerical fields and SOMA name metadata.
3. Reject duplicate joint or body names.
4. Verify every selected file uses one consistent embedded joint/body
   contract.
5. Verify the embedded body sequence exactly matches configured `body_names`.
6. Allow the existing loader to validate and reorder joint columns and build
   transitions.

Sharing the current feature builder preserves the discriminator's established
input order:

1. root height;
2. root orientation 6D;
3. root linear velocity;
4. root angular velocity;
5. joint positions in configured order;
6. joint velocities in configured order;
7. key-body positions in `key_body_names` order, expressed in the root frame.

The current GPU transition-preloading changes in the local RSL-RL worktree are
preserved.

### Dataset selection

Export both loaders from `rsl_rl.datasets`. Add an AMP algorithm setting:

```python
motion_dataset_format = "beyondmimic"  # default
```

`AMP.construct_algorithm` resolves the value through a closed mapping:

- `"beyondmimic"` -> existing `MotionDataset`
- `"soma"` -> new `SomaMotionDataset`

An unknown format raises a descriptive `ValueError`. All existing AMP
configurations retain BeyondMimic behavior when the setting is absent.

## Error Handling

Errors include the offending file and contract mismatch. The loader rejects:

- missing required arrays;
- missing `joint_names` or `body_names`;
- duplicate embedded names;
- inconsistent contracts across selected files;
- configured versus embedded joint-name set mismatches;
- configured versus embedded body sequence mismatches;
- unsupported dataset format names.

Failures are explicit; files are not silently skipped when they claim to be
SOMA data but violate the SOMA contract.

## Testing

Use test-driven development in the local RSL-RL fork. Tests cover:

- selecting the SOMA loader from AMP configuration;
- preserving BeyondMimic as the default;
- rejecting unknown format names;
- requiring embedded joint/body names;
- rejecting duplicate and inconsistent names;
- rejecting a configured 30-body sequence for a 34-body SOMA file;
- accepting the configured 34-body sequence;
- reordering joint position and velocity columns into configured order;
- preserving the established AMP feature and key-body loading order;
- proving adjacent input frames remain adjacent without frame-rate conversion.

After focused unit tests pass, run the complete local RSL-RL test suite that
covers AMP and compile the changed Python modules. No simulator or GPU smoke
test is required for the loader-only change.

## Integration Follow-up

Switching DR02 AMP to the SOMA files is a separate configuration change. That
follow-up must provide:

- a data-generation output whose FPS already matches the intended AMP
  transition frequency;
- the SOMA motion directory and file selection;
- `motion_dataset_format="soma"`;
- the complete new 34-body sequence.
